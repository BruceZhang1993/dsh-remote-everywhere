# 插件 UI 开发规划

日期：2026-10-16。状态：管理 UI 首版已实现并完成下述本地验收；未提交、推送或发布。使用说明见 [plugin-ui.md](plugin-ui.md)。

## 目标与范围

用户安装并启用插件后，能够在 DSH 内找到入口，通过界面完成连接准备、双向配对、设备管理和公网隧道操作，不再依赖管理 CLI 完成基本使用流程。

本方案默认沿用宿主组件、主题、语言与键盘交互。首版交付管理 UI；远端完整聊天、文件编辑和交互式终端不在首版范围。配对成功后提供明确的设备选择与对话使用指引，现有 `remote_*` 工具继续负责远程会话操作。

用户已确认首版以本机 `/usr/lib/deepseek-harness-desktop` 的 **DSH Desktop `0.2.1-alpha.2`** 为唯一宿主兼容验收基线。已直接读取该安装目录的 `resources/app.asar`，核对桌面主包、桌面运行时、Client Modules、Plugin Manager 和 API Gateway 均为 `0.2.1-alpha.2`，不再仅依据缓存判断版本。

`0.1.7-rc.2` 不纳入本次 UI 首版兼容承诺或验收矩阵。现有发布插件以该旧版为基线，因此开发第一步必须核对并适配 `0.2.1-alpha.2` 的后台服务契约、依赖版本与浏览器加载规则，不能仅放宽 peerDependencies 后宣称兼容。Web GUI 如做补充验证，也使用同版宿主；桌面版验收是交付必需项。

## 已核对的实现依据

- `packages/dsh-plugin/src/index.js`：原有运行时、本机管理 socket、模型工具与 skill；本次增加复用同一运行时的宿主管理接口。
- `packages/dsh-plugin/package.json`：已有 `./client` 导出指向 Node 远程客户端；不能直接改成浏览器入口而破坏既有使用方。
- `packages/dsh-plugin/src/pairing.js`：已有单次、180 秒有效的配对和双端 SAS 确认。
- `packages/dsh-plugin/src/store.js`：设备同时记录本机授予对方的 `caps` 与对方授予本机的 `remoteCaps`；不能压成一个含糊的“已连接”状态。
- `packages/tunnel/src/index.js`：已有单进程管理、启动合并、停止、超时、就绪探测和状态事件。
- 实际安装的 `app.asar` 中，`dsh-client-ui-plugin-manager/lib/client.js` 包含 `plugins.bundle.config`、`plugins.bundle.activation` 和 `openBundle`；缓存中的同版文档用于辅助了解接口，最终以安装产物为准。
- 本地宿主文档：浏览器插件由 `dsh.client` 和 `exports["./client"]` 加载，通过 Slots 贡献 React UI。

以上是设计时的代码和本地产物核对依据；实际验收结果另记于本文末尾。

## 入口和页面

主入口为 **插件 → DSH Remote Everywhere**，在组合包详情内直接呈现管理面板。启用后的宿主引导提供“打开远程管理”；已有安装升级后即使不触发启用引导，主入口和空状态说明也始终可见。

侧栏增加“远程设备”快捷入口，跳转同一管理面板；不再创建一份独立管理页。若目标宿主没有适合的侧栏槽位，先保留插件页入口，并明确兼容差异。

```text
DSH Remote Everywhere
本机：工作电脑   服务：运行中   公网访问：未开启

[连接其他 DSH]  [让手机或其他 DSH 连接本机]

设备 | 公网访问 | 使用帮助

设备名称   连接状态   我能控制它   它能控制本机   操作
笔记本     未连接     会话/审批    未授权         连接 · 改名 · 吊销

首次使用：选择连接方向 → 配对 → 双方核对安全码 → 开始使用
```

“已配对”表示存在信任记录；“已连接”必须有当前连接证据。不能把未尝试连接的设备一律标成离线，也不能声称知道没有心跳依据的最后在线时间。

| 区域 | 首版内容 | 关键交互 |
| --- | --- | --- |
| 概览 | 本机名称/设备 ID、服务状态、隧道状态、入门提示 | 后台未运行或失败时给出原因与宿主启用/重启指引 |
| 设备 | 名称、连接状态、授权方向、权限、配对时间 | 连接/断开、改名、吊销；吊销前说明影响并人工确认 |
| 公网访问 | cloudflared 检测、启动/停止、就绪后端点 | 启动中可取消；缺依赖时提供安装/路径配置指引，不自动安装系统软件 |
| 使用帮助 | 两个方向的配对说明、设备 ID 复制、对话使用示例 | 说明手机 App 需单独安装及其分发状态；高级区提供 CLI 与有限诊断 |

服务启停沿用宿主插件管理行为，不新增一个语义重复的“启用插件”开关。UI 伴生包应能在后台暂时不可用时显示状态，而不是整体卡在加载中。

## 核心流程

### 让其他设备连接本机

1. 选择“让手机或其他 DSH 连接本机”。说明默认本机回环端点不能跨设备使用。
2. 跨设备场景选择开启公网隧道；等待真实就绪后才生成可跨设备使用的二维码，不把 loopback 二维码作为手机可连接结果。
3. 选择权限，默认会话/流/人工审批；文件、终端和设备管理明确分项授权。
4. 显示二维码、复制配对信息、180 秒倒计时和取消按钮。复制前说明其为临时配对信息。
5. 对端加入后展示设备身份、权限及六位 SAS；用户人工核对后确认，也可以拒绝。
6. 双端确认并持久化成功才显示完成；一端确认后显示“等待另一端确认”。过期或断线明确显示失败并允许重新生成。

### 本机连接另一台 DSH

1. 选择“连接其他 DSH”，粘贴配对 JSON 或选择配对信息文件。桌面首版不依赖摄像头扫码。
2. 验证格式、期限和端点；展示远端身份及其授予的权限。
3. 经宿主发起加密握手，在界面展示 SAS；双方人工确认后保存信任。
4. 成功页显示目标名称、设备 ID 与“在 DSH 对话中使用”指引。用户可复制明确指定该设备的提示示例。

两个方向各自建立授权，不能把 A 控制 B 描述成双方自动互控。第一版若要调整已配对设备的权限，采用吊销后重新配对，不引入尚无实现的在线增权接口。

### 断线、重启与多窗口

- 关闭管理页只释放观察订阅，不停止已开启的隧道或已建立的连接。
- “取消配对”必须匹配当前配对任务标识，防止旧窗口取消新窗口的配对。
- 重连先获取完整权威快照，再接续状态更新；旧响应不得覆盖新连接代的状态。
- 隧道启动/停止或地址变化时，使绑定旧端点的未完成配对失效，要求重新生成；已配对信任仍绑定原公钥。
- 单纯断线不得隐式撤销信任；端点更新不得替换已固定的公钥。
- 刷新页面不自动重新发起配对、开启隧道或重放写操作。

## 技术方案

### 包结构与交付

新增 `packages/dsh-ui`，注册浏览器 UI；scoped 候选包名为 `@brucezhang1993/dsh-remote-ui`。主插件依赖该包，bundle patch 组合后台与 UI 两行，用户仍只安装主插件。UI 包的 `./client` 专用于浏览器，保留主插件现有 Node SDK 的 `./client` 导出。

UI 使用宿主共享的 React/组件、Slots、语言与主题能力，构建时遵循目标宿主的模块规则。同步更新候选打包、scoped 名称替换、依赖发布顺序、锁文件与消费者安装门禁；不能只修改开发目录后宣称插件安装可用。

### 运行时与管理接口

在当前后台中暴露一个小的管理服务，使 CLI 和 UI 共用同一个运行时、设备存储、配对对象与 TunnelManager。只为必要操作抽取共用入口，不重构远程业务协议。

建议的 UI 管理面包括：

- 脱敏状态快照与可取消状态订阅。
- 入站配对开始、查看、确认、取消。
- 出站配对开始、SAS 确认、取消；将现有交互式回调改为有期限的宿主任务，浏览器不持有身份密钥。
- 设备列表、改名、吊销及出站连接/断开。
- 隧道状态、启动、停止和依赖检测。

管理操作必须通过已确认身份及权限的宿主 UI 通道，不能直接把本机 socket 的 switch 挂到公网，也不能只凭“同源”断言拥有管理权。第一步验证目标宿主能否区分受信任桌面/本机用户和其他调用者；若不能，先设计并验证独立的管理授权，再开放 UI mutation。

前端只保存短期视图状态。身份密钥和信任表继续归宿主所有；配对 JSON/SAS 不写日志或浏览器持久存储。模型工具和远程设备协议不新增本机管理入口，尤其不得替用户完成本机 SAS 确认。

### 状态与生命周期

服务、隧道、配对和设备连接各自持有明确状态，避免用一个布尔值混合表示。观察流先提供快照，再提供有序更新；订阅关闭时释放监听，更新合并且缓冲有界。UI 读取状态不触发任何写入或重新同步。

保持一个 profile 仅一个运行时与隧道资源所有者。多窗口重复点击由宿主合并或拒绝；一次失败不能关闭其他窗口正在使用的共享运行时。配对确认和取消绑定任务标识，过期、被替换和已完成操作具有明确终态。

## 分步开发与验收

| 步骤 | 交付 | 验收标准 |
| --- | --- | --- |
| 1. 目标宿主适配与集成验证 | 适配 Desktop `0.2.1-alpha.2` 的后台服务与依赖，完成 UI 包最小加载、入口与管理授权方案 | 基于实际安装产物的独立 profile 能启动后台并显示入口；禁用/重启无重复入口；未授权调用管理接口被拒绝 |
| 2. 只读管理面板 | 概览、设备列表、隧道状态、空态和错误态 | 状态来自真实运行时；断线/重连能恢复；查看页面不触发配对或启动隧道 |
| 3. 双向配对 | 二维码、粘贴/导入、倒计时、双端 SAS 确认 | 两台真实 DSH 全程通过 UI 配对；覆盖超时、拒绝、重放、旧窗口和重复确认 |
| 4. 设备与公网管理 | 改名、连接/断开、吊销、隧道启停及缺依赖指引 | 吊销立即生效；连续点击只启动一个进程；启动中取消和地址变化正确收敛 |
| 5. 完整安装与 UI 验收 | 包含浏览器产物的候选、使用说明、升级验证 | Desktop `0.2.1-alpha.2` 全新 profile 安装即能使用；旧身份/信任保留；同版 Web 补充验证另记结果 |

验证先覆盖有实际风险的状态机和管理授权，再用真实宿主做端到端流程与截图检查。至少验收浅色/深色、窄窗口、键盘焦点、二维码可扫描性、取消行为和可读错误提示；既有 CLI、MCP、会话与审批回归仍须通过。

所有编译、检查和测试串行放入用户 systemd scope，限制整个进程树为 8 GiB 内存与 4 GiB swap。没有用户 manager 时停止，不能绕过限制执行。

建议安排为一个独立开发里程碑。工期在第 1 步确认宿主授权和构建方式后再估算。验证使用独立 profile，不修改系统安装目录或现用 profile；缓存运行时与系统安装产物不一致时，以后者为准。
